# 서버 배포 파일과 개발 전용 파일

## 서버 런타임 공통 파일

운영 서버와 개발 서버 모두 다음 애플리케이션 소스를 사용한다.

```text
smart_routing/
services/__init__.py
services/api/__init__.py
services/api/common_vrp_config.py
services/api/run_common_vrp_api.py
services/api/sr_vrp_api_server.py
sr_common_vrp_api_server.py
sr_common_vrp_client_server.py
sr_vrp_api_server.py
verify_deployment.py
runtime_env.sh
restart_smart_routing_api.sh
requirements.txt
```

`services/api`는 `smart_routing`을 실행하는 환경 검증·프로세스 어댑터다.
라우팅 알고리즘을 복제한 폴더가 아니다.

## 환경별 서버 파일

운영 패키지에만 포함한다.

```text
start_common_vrp_prod.sh
start_common_vrp_client_server_prod.sh
restart_common_vrp_api.sh
restart_common_vrp_client_server.sh
systemd/common-vrp.service
systemd/common-vrp-client.service
systemd/smart-routing.service
config/common_vrp.prod.template.json
```

개발 서버 패키지에만 포함한다.

```text
bootstrap_common_vrp_dev.sh
start_common_vrp_dev.sh
start_common_vrp_client_server_dev.sh
systemd/common-vrp-dev.service
systemd/common-vrp-client-dev.service
systemd/smart-routing-dev.service
config/common_vrp.dev.template.json
```

두 패키지 모두 `config/config.template.json`과 `config/data_catalog.json`을
포함한다. 실제 secret config는 패키지에 포함하지 않는다.

## 코드 패키지와 별도로 공급하는 서버 데이터

다음은 코드 ZIP에 넣지 않고 승인된 공유 데이터 저장소에서 공급한다.

```text
curated service/profile
reviewed region maps
DB region seed bundle
data/north_america/reference/client/All_In_One_Master.xlsx
data/north_america/reference/geospatial/tl_2024_us_zcta520.zip
heavy-repair 또는 symptom reference
필요한 legacy 260310 input leaf
```

공용 reference는 한 번만 저장하고 읽기 전용으로 제공한다. 작업, 업로드,
cache, report, output은 production/development state로 분리한다. 전체 `data/`
또는 `260310/`을 하나의 writable symlink로 공유하지 않는다.

## 서버 런타임에서 제외하는 파일

다음은 로컬 개발, CI 또는 별도 관리자 배포 범위다.

| 범위 | 분류 |
| --- | --- |
| `admin_tools/db` | 별도 DB 관리자 도구; 런타임 ZIP과 분리 배포 |
| `services/deploy` | 로컬·CI 패키지 빌더 |
| `services/tests`, 루트 `tests` | 테스트 전용 |
| `tools` | 전처리·분석·데이터 승격 도구 |
| `osrm` 및 `osrm-*.service` | `/home/osrm` 별도 운영 패키지 |
| `prompts` | 오프라인 전처리 도구 자산 |
| `docs` | 로컬 문서, `-IncludeDocs` 선택 시에만 포함 |
| 루트 `run_*.ps1`, `run_*.bat` | Windows 개발 실행기 |
| `sr_area_map*.py`, `sr_production_map.py`, `sr_live_atlanta_routing.py` | 분석·운영 도구 UI |
| `sr_common_vrp_client.py`, `sr_common_vrp_client_asia.py`, `sr_vrp_api_client.py` | 비표준/로컬 클라이언트 |
| `.codex`, `.git`, IDE 설정, 로그와 cache | 로컬 상태 |

## 생성되는 서버 패키지

```text
deployment/
├─ production/
│  ├─ <version>/
│  │  ├─ smart_routing/
│  │  └─ services/api/
│  └─ ai-routing-runtime-production-<version>.zip
└─ development/
   ├─ <version>/
   │  ├─ smart_routing/
   │  └─ services/api/
   └─ ai-routing-runtime-development-<version>.zip
```

저장소 루트의 `smart_routing/`, `services/`가 개발 작업본이다. 개발 완료 후
빌드 스크립트가 검증된 런타임 파일만 `deployment/` 아래로 복사한다.
`deployment/` 파일은 직접 수정하지 않으며 `.gitignore` 대상으로 관리한다.

개발 서버 패키지도 로컬 저장소 전체가 아니라 승인된 런타임과 개발 환경
overlay만 포함한다. 운영 패키지는 clean commit에서만 생성할 수 있다.

DB 관리자 도구는 별도 승격본으로 생성한다.

```text
deployment/admin_tools/<version>/
deployment/admin_tools/ai-routing-admin-tools-<version>.zip
  → /home/csda/AI_Routing/admin_tools/releases/<version>/
```

이 패키지는 `admin_tools/`와 동일 revision의 필요한 `smart_routing/` 소스만
포함하며 실제 config, secret, DB 데이터, 입력 데이터는 포함하지 않는다.
